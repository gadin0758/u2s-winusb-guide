# WinUSB 下完整备份

U2S 串口无法写入时，原串口备份脚本也会失败。WinUSB 配合 LibUSB 可提供另一条通信路径，但仍需正确进入 FDL2。先按 [主教程](../README.md) 切换目标驱动并加载 FDL2。

## 备份范围

简单说，就是把脚本能读到的**系统、开机需要的文件、基带和联网相关设置，以及用户数据**都保存下来。两套基带和相关配置都会保留，不是只备份当前使用的一套。

备份时只是把文件读到电脑上，**不会修改或清空设备里的数据**。备份后请保留整个文件夹，不要只挑几个文件留下。

本案例的备份约 **31 GB**，所以需要准备足够的电脑空间。你的设备可能不同，文件数量和大小不一定一样，不能只靠“是不是 31 GB”来判断成功。

这里的“完整”指脚本能读取的全部分区和启动加载器。有些特殊硬件区域无法通过这套方法读取，所以不代表整颗存储芯片里的每个字节都已备份。具体读取范围见 [验证说明](validation.md)。

## 为什么不用 `r all`

因为这个版本的 `r all` 虽然名字里有“all”，实际上会跳过部分内容，包括用户数据，不能满足这里的完整备份要求。[上游说明](https://github.com/TomKing062/spreadtrum_flash/blob/2a202404a7512026d146b62624f089aceb408520/README_zh.md) 写明了这些限制。

另外，上游工具读取某些联网配置时会换到另一份配置，并省略开头的一部分。本脚本按设备里的实际位置读取，目的是把两份原始配置都完整留下。想了解具体原因，可以看 [命令说明](commands.md)。

## 执行与检查

1. 磁盘不能是 FAT32。保留至少 35 GB 空间；若还要刷写并保存读回镜像，建议预留更多。脚本根据本机分区总大小检查剩余空间。
2. 上游工具已显示 `FDL2 >`，在空闲提示符按 Ctrl+C 退出主机程序，不拔线、不重启。
3. 使用一个**不存在的新输出目录**：

```powershell
python .\scripts\f50.py backup --dll C:\F50Tools\spd_dump_LibUSB_Release\libusb-1.0.dll --out C:\F50Tools\backups\B15-original
```

4. 等待全部读取结束。每隔约 30 秒显示进度，大文件读取可能持续较久；案例约需二十余分钟，具体取决于接口和磁盘。不要因短暂没有新输出而断电。
5. 离线校验：

```powershell
python .\scripts\f50.py verify-backup --backup C:\F50Tools\backups\B15-original
```

第二条命令会检查文件有没有漏掉、大小对不对、内容有没有变化。**正常结束并显示 `BACKUP VERIFIED`，才算这份备份通过检查。** 创建了文件夹、里面有很多文件，都不能单独证明备份成功。

## 失败、续读与保存

### 怎么知道备份到哪一步了？

| 你看到的情况 | 说明什么 | 接下来怎么做 |
| --- | --- | --- |
| 窗口还在显示文件名、百分比或读取速度 | 正在备份，还没结束 | 保持连接，继续等；短暂没新文字不代表卡死 |
| 文件夹里有 `.partial` 结尾的文件 | 这个文件还没读完；运行中也会出现 | 如果程序还在跑，先等；如果程序已报错或退出，这份备份就还不能用 |
| 窗口最后显示 `COMPLETE ... files ... bytes`，程序正常结束 | 全部读取步骤已完成 | 再运行上面的 verify-backup 检查命令 |
| 检查命令正常结束，并显示 `BACKUP VERIFIED` | 这份备份通过检查 | 整个文件夹保留下来，再复制一份到其他磁盘 |
| 出现 `STOPPED:`、报错，或程序在显示 COMPLETE 之前退出 | 没有完成，或检查没通过 | 先保存报错内容，查清原因，不继续刷写 |

还可以用记事本打开备份目录里的 `verified-manifest.json`，找 `complete`：`true` 表示脚本已经读完，`false` 表示还没完成。如果这个文件都没有生成，也不能算完成。**即使写着 true，仍要运行检查命令并看到 BACKUP VERIFIED。不要自己把 false 改成 true。**

### 失败了能接着上次读吗？

目前不能。脚本不会从上次断掉的位置接着读，也不会覆盖旧文件。

先保留旧目录和报错内容，让 AI 或懂这套流程的人检查数据线、驱动、磁盘空间和连接状态。确认只是备份阶段、没有刷写正在进行后，按主教程重新进入 `FDL2 >`，再在空闲提示符关闭上游程序。然后把 `--out` 换成一个**还不存在的新目录**，从头备份，例如：

```powershell
python .\scripts\f50.py backup --dll C:\F50Tools\spd_dump_LibUSB_Release\libusb-1.0.dll --out C:\F50Tools\backups\B15-retry
python .\scripts\f50.py verify-backup --backup C:\F50Tools\backups\B15-retry
```

不要把上次没读完的文件和新备份混在一起。如果你已经开始刷系统，这里的“重新连接后再读”不能直接照做，应先检查刷写停在了哪一步。

以前用其他脚本做过的备份，也不要只改文件名就拿来用。如果当前检查命令不接受它，先核对旧备份的内容，不要删掉检查或修改清单来让它勉强通过。

### 成功以后怎么保存？

把**整个备份文件夹**复制到另一块磁盘，里面的镜像、清单和校验文件都要留着。不要只留基带文件，恢复设备时还可能需要其他文件。

复制后再检查一次，路径换成复制品的位置。例如复制到了 `D:\F50Backup\B15-original`：

```powershell
python .\scripts\f50.py verify-backup --backup D:\F50Backup\B15-original
```

复制品也显示 `BACKUP VERIFIED`，才算检查通过。

**备份留在自己电脑或私人磁盘里，不要上传公开仓库。** 里面可能含设备身份、联网设置、密码和个人数据。给 AI 看报错时，也只提供去掉个人信息的必要文字，不上传整套备份。
